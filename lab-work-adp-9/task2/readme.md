# Курс: Шаблоны проектирования приложений

## Тема: Модуль 09  Структурные паттерны.  Фасад. Компоновщик


### Цель:
Изучить и реализовать структурный паттерн Компоновщик (Composite) на языке C# для организации древовидной структуры объектов.
### Теоретическая справка:
**Компоновщик (Composite)** — это структурный паттерн проектирования, который позволяет объединить объекты в древовидные структуры для представления иерархии "часть-целое". Компоновщик позволяет клиентам работать с отдельными объектами и группами объектов одинаково.

### Пример:
Паттерн Компоновщик можно использовать для создания системы управления файлами и папками, где как файлы, так и папки могут рассматриваться как единые объекты. Папка может содержать как файлы, так и другие папки, и с любым из этих объектов можно работать одинаково.
Задачи:
1.	Реализовать абстрактный класс Component, представляющий как листовые элементы (например, файлы), так и контейнеры (например, папки).
2.	Создать класс File, представляющий конкретный листовой элемент (файл).
3.	Создать класс Directory, представляющий контейнер, который может содержать файлы и другие директории.
4.	Написать клиентский код, демонстрирующий работу паттерна Компоновщик.



## Вопросы для закрепления:
### 1. В чем заключается суть паттерна Компоновщик?
Компоновщик это структурный паттерн проектирования, который позволяет сгруппировать множество объектов в древовидную структуру, а затем работать с ней так, как будто это единичный объект.
### 2. В каких случаях удобно использовать паттерн Компоновщик?
Когда есть повторяющиеся древрвидная структура
### 3. Какие преимущества и недостатки имеет паттерн **Компоновщик (Composite)**?
Паттерн Компоновщик упрощает работу с иерархическими структурами объектов, позволяя клиенту одинаково обращаться как к отдельным элементам, так и к их группам. Он облегчает расширяемость системы и делает код более гибким и универсальным. Однако из-за рекурсивной природы структуры усложняется отладка и контроль над составом компонентов, а в простых случаях применение паттерна может быть избыточным и усложнять архитектуру.
### 4. Какие другие паттерны структурного проектирования могут использоваться вместе с паттерном **Компоновщик (Composite)**?
Паттерн Компоновщик часто применяется совместно с другими структурными шаблонами: Фасад используется для упрощённого управления всей иерархией, Декоратор — для добавления нового поведения отдельным элементам, Легковес — для оптимизации памяти при множестве однотипных объектов, Прокси — для контроля доступа к компонентам, а Цепочка обязанностей — для передачи событий или команд по структуре дерева.
